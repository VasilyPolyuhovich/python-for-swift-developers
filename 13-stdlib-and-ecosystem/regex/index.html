    Регулярні вирази: модуль re¶

    ← Курс · Модуль 13 · Регулярні вирази (re)

    Регулярні вирази в Python — це stdlib-модуль re (без імпорту бібліотек). У Swift ти користувався NSRegularExpression (важкий, з NSRange) або новим типобезпечним Regex / #/.../# literal (Swift 5.7+). Python ближчий до старого світу: патерн — це рядок, результат — Match-об'єкт.

    // Swift
let re = try! NSRegularExpression(pattern: #"\d+"#)
let m = re.firstMatch(in: "a12", range: NSRange("a12".startIndex..., in: "a12"))

    import re
m = re.search(r"\d+", "a12")          # m.group() == '12'

    Коли re, а коли методи str¶

    Спершу — найважливіше правило (перегукується з Модуль 01 · Рядки):

    Best practice. Якщо задачу вирішують split / replace / partition / startswith — бери їх. Вони швидші, читабельніші й не ламаються на edge-cases. re потрібен, коли є справжній патерн (змінна структура, класи символів, повтори, варіанти), а не фіксований роздільник.

    "a,b,c".split(",")            # ✅ простий роздільник — НЕ потрібен re
text.replace("foo", "bar")    # ✅ фіксована заміна — НЕ потрібен re
re.split(r"[,;]\s*", text)    # ✅ кілька роздільників + пробіли — ось тут re

    Raw-рядки r"..." — завжди¶

    Патерни завжди пиши як raw-рядки. Причина: \ — escape і в синтаксисі рядків Python, і в мові regex. Без r вони конфліктують.

    "\d"     # SyntaxWarning: invalid escape sequence — лишається '\\d', але це удача
"\b"     # '\x08' — це BACKSPACE-символ, а не "межа слова" regex!
r"\b"    # '\\b' — два символи: бекслеш + b. Саме це треба regex-движку.

    ⚠️ Пастка. Забув r — і "\b" стає символом backspace, а патерн тихо перестає працювати як «межа слова». \d, \s поки що дають лише SyntaxWarning, але в майбутніх версіях стануть помилкою. Правило просте: кожен regex-патерн — r"...".

    Базові функції¶

    Функція Що робить
    re.match(p, s) збіг на початку рядка (не з кінця)
    re.search(p, s) перший збіг будь-де
    re.fullmatch(p, s) весь рядок цілком має збігтися
    re.findall(p, s) список усіх збігів (рядки або кортежі груп)
    re.finditer(p, s) ітератор Match-об'єктів (з позиціями)
    re.sub(p, repl, s) заміна всіх збігів
    re.subn(p, repl, s) те саме + кількість замін
    re.split(p, s) розбити за патерном

    match vs search — найчастіша плутанина¶

    match прив'язаний до початку рядка (наче неявний ^), search шукає будь-де:

    re.match(r"\d+", "abc123")     # None     — на початку цифр немає
re.search(r"\d+", "abc123")    # <Match span=(3, 6) match='123'>
re.match(r"\d+", "123abc")     # <Match span=(0, 3) match='123'>  — є на початку
re.fullmatch(r"\d+", "123abc") # None     — весь рядок НЕ цифри
re.fullmatch(r"\d+", "123")    # <Match span=(0, 3) match='123'>

    ⚠️ Пастка. match НЕ означає «знайти збіг». Для пошуку «чи є десь патерн» майже завжди потрібен search. match — лише коли валідуєш початок рядка.

    findall / finditer¶

    re.findall(r"\d+", "a12 b34 c5")        # ['12', '34', '5']
re.findall(r"(\w)(\d)", "a1 b2")        # [('a', '1'), ('b', '2')]  — кортежі груп!

for m in re.finditer(r"\d+", "a12 b34"):
    print(m.group(), m.span())
# 12 (1, 3)
# 34 (5, 7)

    ⚠️ Пастка. Якщо в патерні є групи, findall повертає групи, а не повний збіг. Один збіг → рядок; ≥2 групи → кортеж. Потрібен повний збіг разом із позиціями — бери finditer.

    Match-об'єкт¶

    search/match повертають Match або None. Звертатися до .group() у None не можна:

    m = re.search(r"\d+", "abc")
m                  # None
m.group()          # AttributeError: 'NoneType' object has no attribute 'group'

    ⚠️ Пастка. Завжди перевіряй результат: if m := re.search(...): (walrus), інакше AttributeError на порожньому збігу.

    m = re.search(r"(\w+)@(\w+)\.(\w+)", "user@host.com")
m.group(0)        # 'user@host.com'   — весь збіг (== m.group())
m.group(1)        # 'user'            — перша група
m.groups()        # ('user', 'host', 'com')
m.start(), m.end(), m.span()    # (0, 13, (0, 13))
m.start(1)        # 0               — позиція конкретної групи

    Іменовані групи (?P<name>...) + .groupdict():

    m = re.search(r"(?P<user>\w+)@(?P<host>\w+)", "vasyl@example")
m.groupdict()     # {'user': 'vasyl', 'host': 'example'}
m.group("user")   # 'vasyl'

    Групи¶

    re.findall(r"(?:ab)+(\d)", "ababab7")   # ['7']  — (?:...) групує, але НЕ захоплює
re.findall(r"(\w)\1", "hello bookkeeper")  # ['l', 'o', 'k', 'e']  — backreference
bool(re.search(r"(\w+) \1", "the the cat"))  # True  — повторене слово
    • (...) — захоплююча група (нумерується з 1).
    • (?:...) — групує без захоплення (швидше, не засмічує .groups()).
    • (?P<name>...) — іменована.
    • \1, \2 — backreference: «той самий текст, що зловила група N».

    Заміна: re.sub¶

    У repl доступні \1 / \g<name>, або передай функцію:

    re.sub(r"(\w+)@(\w+)", r"\2.\1", "user@host")        # 'host.user'
re.sub(r"(?P<y>\d{4})-(?P<m>\d{2})", r"\g<m>/\g<y>", "2025-06")   # '06/2025'

# функція як заміна — будь-яка логіка над збігом
re.sub(r"\d+", lambda mo: str(int(mo.group()) * 2), "a3 b5")      # 'a6 b10'

re.subn(r"o", "0", "foobar")     # ('f00bar', 2)  — ще й лічильник

    ⚠️ Пастка. У рядку заміни теж пиши raw (r"\1"), інакше \1 може стати октальним escape. \g<name> однозначно посилається на іменовану групу.

    Метасимволи (швидкий довідник)¶

    Символ Значення Символ Значення
    . будь-який (крім \n) ^ $ початок / кінець
    \d \D цифра / не-цифра \b межа слова
    \w \W літера/цифра/_ / ні [abc] клас символів
    \s \S пробіл / не-пробіл [^abc] заперечений клас
    * 0+ a|b альтернатива
    + 1+ {2,5} від 2 до 5
    ? 0 або 1 {3} рівно 3

    Greedy vs lazy — пастка жадібності¶

    Квантори * + ? {} за замовчуванням жадібні — хапають якомога більше. Додай ? після квантора, щоб зробити «лінивим» (мінімум):

    re.findall(r"<.*>", "<a><b>")     # ['<a><b>']   — жадібний: один великий збіг
re.findall(r"<.*?>", "<a><b>")    # ['<a>', '<b>']  — лінивий: кожен тег окремо

    ⚠️ Пастка. .* між роздільниками майже завжди має бути .*?, інакше «з'їдає» все до останнього роздільника. Класична помилка при парсингу HTML/тегів.

    Прапорці (flags)¶

    re.findall(r"py", "Python PyPI py", re.IGNORECASE)   # ['Py', 'Py', 'py']
re.findall(r"^\w+", "foo\nbar\nbaz", re.MULTILINE)   # ['foo', 'bar', 'baz'] — ^ на кожному рядку
bool(re.search(r"a.b", "a\nb", re.DOTALL))           # True — . матчить і \n
bool(re.match(r"(?i)hello", "HELLO"))                # True — inline-прапорець (?i)
    • re.IGNORECASE — без регістру.
    • re.MULTILINE — ^/$ працюють на кожному рядку, не лише на краях.
    • re.DOTALL — . включає \n.
    • re.VERBOSE — дозволяє пробіли й коментарі в патерні (читабельність).

    re.VERBOSE для складних патернів:

    pat = re.compile(r"""
    (\d{4})   # year
    -
    (\d{2})   # month
""", re.VERBOSE)
pat.match("2025-06").groups()      # ('2025', '06')

    Best practice. Як тільки патерн перестає вміщатися в один погляд — переписуй на re.VERBOSE з коментарями. Це Python-аналог «розбити складний Regex на названі частини». Інлайн (?i), (?m) зручні, коли прапорець не хочеться нести окремим аргументом.

    re.compile — для повторного використання¶

    Якщо патерн застосовується багато разів (цикл, гаряча функція), компілюй один раз:

    p = re.compile(r"\d+")
p.findall("a1 b22")       # ['1', '22']
p.search("xx99").group()  # '99'

    Best practice. Скомпільований патерн має ті самі методи (.search, .findall, .sub, ...). У модулі-рівні re кешує останні ~512 патернів, тож для разових викликів re.search(r"...", s) теж нормально. compile — про читабельність (іменований патерн) + гарантований performance у циклах.

    Практичні рецепти¶

    # Валідація email-подібного рядка (НЕ повний RFC — для форм достатньо)
bool(re.match(r"[^@\s]+@[^@\s]+\.[^@\s]+", "a@b.com"))   # True

# Витягти числа (цілі + дробові + знак)
re.findall(r"-?\d+\.?\d*", "x=3, y=-4.5, z=10")          # ['3', '-4.5', '10']

# Розпарсити key=value у dict
dict(re.findall(r"(\w+)=(\w+)", "a=1 b=2 c=3"))          # {'a': '1', 'b': '2', 'c': '3'}

# Усі слова (з Unicode-літерами)
re.findall(r"\b\w+\b", "Hello, world! Привіт")           # ['Hello', 'world', 'Привіт']

# Нормалізувати пробіли
re.sub(r"\s+", " ", "a  b\t\nc")                         # 'a b c'

# Розбити за кількома роздільниками
re.split(r"[\s,;]+", "a, b;c  d")                        # ['a', 'b', 'c', 'd']

# Slug із заголовка
re.sub(r"[^a-z0-9]+", "-", "Hello, World!".lower()).strip("-")   # 'hello-world'

    Catastrophic backtracking (ReDoS)¶

    Деякі патерни на «поганому» вході вибухають експоненційно за часом — це вразливість ReDoS. Винуватці — вкладені квантори на пересічних класах, як (a+)+, (\w+)*$, (.*)*.

    # ❌ небезпечно: на рядку "aaaa...aaaX" зависне надовго
re.match(r"(a+)+$", "a" * 30 + "X")

    ⚠️ Пастка. Тримай патерни простими й однозначними; уникай вкладених квантори-на-кванторі. Не запускай regex на недовіреному вводі без таймауту/ліміту довжини. Для складних потреб (атомарні групи, можливі квантори, fuzzy-match, кращий Unicode) є PyPI-модуль regex — drop-in заміна re з ширшими можливостями.

    Шпаргалка / рецепти¶

    import re

re.search(r"pat", s)               # перший збіг будь-де (None якщо немає)
re.match(r"pat", s)                # збіг лише НА ПОЧАТКУ
re.fullmatch(r"pat", s)            # весь рядок цілком
if m := re.search(r"(\d+)", s):    # безпечна перевірка перед .group()
    m.group(1)

re.findall(r"\d+", s)              # усі збіги списком
re.finditer(r"\d+", s)             # + позиції (.span())
re.sub(r"\s+", " ", s)             # нормалізація пробілів
re.split(r"[,;]\s*", s)            # розбити за кількома роздільниками

p = re.compile(r"\d+")             # компіляція для циклів
re.compile(r"...", re.VERBOSE)     # читабельний складний патерн

# Жадібність: .*  →  .*?  (лінивий) між роздільниками
# Прапорці: IGNORECASE | MULTILINE | DOTALL | VERBOSE
# ЗАВЖДИ raw-рядок: r"\d", r"\b"
