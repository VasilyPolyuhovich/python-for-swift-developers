# Кортежі (`tuple`)

[← Курс](../README.md) · [Модуль 03](../03-data-structures.md) · **tuple**

У Swift кортеж — це `(a, b)`: легкий складений тип, поля можуть бути іменованими
(`(x: 3, y: 4)`). У Python `tuple` — це **незмінна, упорядкована послідовність**.
Звичайний кортеж **позиційний** (без імен полів) — звертання лише за індексом.
Для іменованих полів є `NamedTuple`/`@dataclass` ([Модуль 06](../06-structs-and-value-types.md)).

```swift
// Swift: поля можуть мати імена, тип фіксований і гетерогенний
let point = (x: 3, y: 4)
point.x            // 3
```

```python
point = (3, 4)     # позиційний; полів-імен немає
point[0]           # 3
```

Ключова відмінність від `list` випливає з незмінності: **кортеж гешований**
(якщо гешовані всі елементи), тож його можна класти в `dict` як ключ або в `set`.
`list` так не вміє. Це й робить `tuple` «value-подібним».

> **⚠️ Найчастіша помилка.** Кортеж не має методів зміни (`append`, `sort`,
> присвоєння за індексом). Усе, що «змінює» — створює **новий** кортеж. Потрібна
> мутація на місці → бери `list`.

---

## 1. Створення та літерали

```python
pair = (1, 2)
triple = 1, 2, 3            # дужки часто НЕ обов'язкові — кому робить кортеж
empty = ()                 # порожній кортеж
from_iter = tuple("abc")   # ('a', 'b', 'c')  — з будь-якого ітерабельного
```

Кортеж створює саме **кома**, а не дужки. Звідси найвідоміша пастка:

```python
type((5))      # int     — це просто число в дужках!
type((5,))     # tuple   — trailing comma робить кортеж із одного елемента
type(())       # tuple   — а порожні дужки таки кортеж
```

> **⚠️ Пастка одного елемента.** `(x)` — це `x`, а не кортеж. Кортеж із одного
> елемента — `(x,)` з **обов'язковою** комою. Часта причина багів:
> `return (value,)` vs `return (value)`.

---

## 2. Пакування та розпакування

Кома праворуч «пакує», кома ліворуч «розпаковує» — це основна ідіома Python.

```python
point = 3, 4               # пакування
x, y = point               # розпакування → x=3, y=4

a, b = 10, 20
a, b = b, a                # обмін без temp → a=20, b=10
```

Розпакування зі «зірочкою» (`*`) збирає решту в `list`:

```python
t = (1, 2, 3, 4)
first, *rest = t           # first=1,  rest=[2, 3, 4]
*init, last = t            # init=[1, 2, 3],  last=4
a, (b, c) = 1, (2, 3)      # вкладене → a=1, b=2, c=3
```

> **⚠️ Пастка.** Те, що збирає `*`, — завжди `list`, навіть із кортежу:
> `rest == [2, 3, 4]`, не `(2, 3, 4)`. І зірочка в розпакуванні може бути лише
> одна (інакше неоднозначно, де кінець).

---

## 3. Індексація, зрізи та (відсутні) методи

Кортеж — послідовність, тож індекси/зрізи працюють як у `list`/`str`
(повна механіка зрізів — [list](list.md)):

```python
t = (10, 20, 30, 40)
t[0]        # 10
t[-1]       # 40       від'ємний індекс — з кінця
t[1:3]      # (20, 30) зріз кортежу → знову tuple
len(t)      # 4
20 in t     # True
```

Через незмінність зміна за індексом неможлива, а методів лише два:

```python
t[0] = 99   # ❌ TypeError: 'tuple' object does not support item assignment
t.count(20) # 1   скільки разів трапляється
t.index(30) # 2   індекс першого входження (ValueError, якщо немає)
```

## 4. Кортеж як ключ `dict` / елемент `set`

Незмінність → гешованість → кортеж можна використати там, де `list` дасть помилку.
Класичний приклад — координати як ключ:

```python
grid = {}
grid[(0, 0)] = "start"
grid[(1, 2)] = "treasure"
grid[(1, 2)]                   # 'treasure'

seen = {(1, 2), (3, 4), (1, 2)}
seen                           # {(1, 2), (3, 4)}  — дублікат злився
```

> **⚠️ Пастка: незмінний кортеж із мутабельним всередині.** Незмінність кортежу
> «поверхнева» — він фіксує самі **посилання**, але якщо елемент сам мутабельний,
> його можна змінити. Такий кортеж тоді **не гешований**:

```python
t = ([1, 2], 3)
t[0].append(9)
t                              # ([1, 2, 9], 3)  — мутація спрацювала!

d = {t: "x"}
# ❌ TypeError: unhashable type: 'list'  (кортеж із mutable-елементом не гешується)
```

> **Best practice.** Хочеш гешований кортеж — клади в нього лише незмінні
> елементи (`int`, `str`, інші кортежі, `frozenset`). Список-усередині ламає
> і незмінність «на ділі», і гешованість.

## 5. Повернення кількох значень з функції

Кілька значень із функції в Python — це **кортеж** (часто без дужок). Викликач
розпаковує його ([Модуль 02](../02-functions.md)):

```python
def min_max(xs):
    return min(xs), max(xs)    # пакується в кортеж

min_max([3, 1, 4, 1, 5])       # (1, 5)  — це один tuple
lo, hi = min_max([3, 1, 4, 1, 5])   # розпакування → lo=1, hi=5
```

Це прямий аналог Swift-функції, що повертає `(min: Int, max: Int)` — тільки без
імен полів на боці Python.

---

## 6. Анотації типів

Для типізації ([Модуль 04](../04-types-and-typing.md)) є дві форми:

```python
pair: tuple[int, str]          # ФІКСОВАНА довжина, гетерогенний: рівно (int, str)
row:  tuple[int, ...]          # ЗМІННА довжина, гомогенний: будь-скільки int
```

`tuple[int, str]` каже «два елементи, перший `int`, другий `str`» — як Swift-кортеж
`(Int, String)`. `tuple[int, ...]` — «послідовність `int` довільної довжини»
(це той випадок, коли часто доречніший `list`).

---

## 7. Кортеж як легкий запис — і його межа

Кортеж зручний як разовий «запис», поки полів мало й контекст очевидний. Але
позиційність швидко стає нечитабельною:

```python
p = (3, 4)
p[0], p[1]      # (3, 4)  — що таке [0]? x? width? широта?
```

Коли полів стає багато або їх плутають — переходь на іменовані поля
([Модуль 06](../06-structs-and-value-types.md)):

```python
from typing import NamedTuple

class Point(NamedTuple):
    x: int
    y: int

p = Point(3, 4)
p.x, p.y        # (3, 4)  — читабельно, і досі tuple
p[0]            # 3       — індексація теж працює
```

> **Best practice.** Безіменний `tuple` — для 2–3 полів у локальному контексті
> (повернення з функції, ключ словника). Більше полів або «довге життя» запису →
> `NamedTuple` (незмінний, як tuple) чи `@dataclass` (мутабельний, з методами).

---

## 8. Продуктивність: `tuple` vs `list`

Кортеж трохи компактніший і швидший за `list` (фіксований розмір, без запасу під
зростання):

```python
import sys
sys.getsizeof((1, 2, 3))    # 72   байт
sys.getsizeof([1, 2, 3])    # 88   байт
```

> **Best practice.** Для **фіксованого гетерогенного** набору даних (координата,
> RGB, рядок результату) бери `tuple` — він декларує «це не зміниться» і дешевший.
> Для **однорідної колекції, що зростає/змінюється** — `list`.

---

## Шпаргалка / рецепти

```python
single = (x,)                      # кортеж із одного елемента (кома!)
empty = ()                         # порожній кортеж
t = tuple(iterable)                # з ітерабельного

x, y = point                       # розпакування
a, b = b, a                        # обмін значень
first, *rest = t                   # голова + хвіст (rest — list)
*init, last = t                    # усе + останній

return min(xs), max(xs)            # кілька значень із функції
grid[(row, col)] = value           # кортеж як ключ словника

pair: tuple[int, str]              # фіксований гетерогенний
row:  tuple[int, ...]              # змінний гомогенний

# іменовані поля замість p[0]/p[1]:
class Point(NamedTuple):
    x: int
    y: int
```
