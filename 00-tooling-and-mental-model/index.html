    Модуль 00. Інструментарій і ментальна модель¶

    ← Курс · Тематичний індекс · Модуль 00

    Перш ніж писати код, треба налаштувати середовище й перебудувати кілька базових уявлень. Цей модуль — фундамент: тут менше синтаксису, але без нього все інше буде на хиткій основі. Якщо ти прийшов зі Swift, найбільша робота тут — не вивчити нове, а відучитися від двох звичок: «змінна володіє значенням» і «типи перевіряє компілятор».

    1. Ментальна модель: чим Python принципово інший¶

    Як це у Swift¶

    • Компільована мова: swiftc перетворює код у машинний бінарник.
    • Статична типізація: типи перевіряються на етапі компіляції. Помилка типу не дає програмі зібратися.
    • Value semantics за замовчуванням: struct, enum, Array, Dictionary копіюються при присвоєнні.
    • ARC керує пам'яттю для reference-типів (class).

    Як це в Python¶

    • Інтерпретована мова (точніше — компіляція в байткод + виконання у віртуальній машині CPython). Немає окремого кроку збірки бінарника.
    • Динамічна типізація: тип належить значенню, а не змінній. Змінна — це просто ім'я, прив'язане до об'єкта. Перевірка типів — у рантаймі (або опціонально статичним аналізатором, див. Модуль 04).
    • Reference semantics завжди: усе є об'єктом, змінна тримає посилання на об'єкт. Це найважливіший зсув мислення.
    • Пам'яттю керує reference counting + garbage collector для циклів.
    # 'x' — це ім'я, прив'язане до об'єкта-списку.
x = [1, 2, 3]
y = x          # y вказує на ТОЙ САМИЙ список, не на копію
y.append(4)
print(x)       # [1, 2, 3, 4]  — змінили через y, але x теж "побачив"

    // Swift: Array — value type, тут була б копія
var x = [1, 2, 3]
var y = x        // y — НЕЗАЛЕЖНА копія
y.append(4)
print(x)         // [1, 2, 3]

    ⚠️ Пастка №1 для Swift-розробника. У Python немає struct із value semantics. Якщо тобі потрібна семантика копіювання — копіюй явно (copy.deepcopy, або immutable-типи на кшталт tuple, frozen dataclass). Детально — у Модулі 06.

    Імена vs об'єкти — правильна метафора¶

    У Swift корисно думати «змінна — це коробка зі значенням». У Python ця метафора шкідлива. Правильна модель: об'єкти живуть у купі, а імена — це наклейки, які до них чіпляються. = ніколи не копіює об'єкт — він лише чіпляє наклейку.

    x = [1, 2, 3]     # створили список-об'єкт, наклеїли на нього ім'я x
y = x             # ще одна наклейка на ТОЙ САМИЙ об'єкт
del x             # зняли наклейку x; об'єкт живий, бо є y

    Це пояснює все інше: чому передача у функцію не копіює, чому is ≠ ==, чому mutable default arguments — пастка (див. Модуль 02).

    «Усе — об'єкт»¶

    У Python функції, класи, модулі, типи — це теж об'єкти. Їх можна передавати в змінні, повертати з функцій, класти у списки. У Swift функції є first-class, але типи й модулі — ні.

    def greet(name: str) -> str:
    return f"Hi, {name}"

f = greet           # функція як значення
print(f("Vasyl"))   # Hi, Vasyl
print(type(int))    # <class 'type'>  — навіть int є об'єктом

    Навіть тип — це об'єкт типу type, а сам type — теж об'єкта типу type (рекурсія тут зупиняється):

    type(int)      # <class 'type'>
type(type)     # <class 'type'>   — кільце замикається
int.__mro__    # (<class 'int'>, <class 'object'>)  — ланцюг успадкування

    Це не академічна дрібниця: на цьому стоять метакласи, декоратори й уся інтроспекція (Модуль 05).

    2. Як CPython насправді виконує код¶

    «Інтерпретована» — спрощення. Насправді відбувається два кроки:

    1. Компіляція в байткод. Вихідний .py компілюється у платформо-незалежний байткод — послідовність інструкцій для віртуальної машини.
    2. Виконання у PVM. Python Virtual Machine (цикл обчислення в CPython) виконує ці інструкції одну за одною.

    Подивитися байткод можна модулем dis:

    import dis
dis.dis(lambda x: x + 1)

      1   RESUME                   0
      LOAD_FAST_BORROW         0 (x)
      LOAD_SMALL_INT           1
      BINARY_OP                0 (+)
      RETURN_VALUE

    Конкретні опкоди залежать від версії (приклад вище — 3.14; у 3.13 буде LOAD_FAST/LOAD_CONST). Сенс не в назвах, а в розумінні: між твоїм кодом і «залізом» є проміжний шар, і саме його накладні витрати роблять чистий Python повільнішим за Swift. Гарячі цикли виносять у C-розширення (NumPy) або оптимізують (див. профілювання нижче).

    Кеш байткоду: .pyc і __pycache__¶

    Щоб не перекомпільовувати щоразу, CPython кешує байткод модулів у теку __pycache__/:

    mypackage/
  module.py
  __pycache__/
    module.cpython-314.pyc     # кешований байткод для CPython 3.14
    • Кешуються лише імпортовані модулі, не той файл, що ти запускаєш напряму.
    • Кеш інвалідовується автоматично (за хешем/часом зміни). Чіпати його руками не треба; у .gitignore додай __pycache__/.
    • Цикл «redeploy» у Python тривіальний: немає лінкера, немає бінарника — просто замінив .py.

    Best practice. Не коміт .pyc/__pycache__. uv init і стандартні .gitignore для Python уже їх виключають.

    3. Модель об'єктів і пам'ять¶

    Кожен об'єкт має три речі: ідентичність (адресу), тип і значення.

    is vs ==, та id()¶

    a = [1, 2, 3]
b = a
c = a.copy()

a is b        # True   — той самий об'єкт (та сама ідентичність)
a is c        # False  — різні об'єкти
a == c        # True   — рівні за значенням
id(a) == id(b)  # True — id() повертає ідентичність (≈ адресу)

    is — це Swift === (тотожність посилання). == — це == (рівність значень, яку задає __eq__, Модуль 05). Для None/True/False завжди is (вони — синглтони).

    Reference counting і збирач сміття¶

    Базовий механізм — підрахунок посилань: коли лічильник падає до нуля, об'єкт негайно звільняється. Окремий garbage collector добиває циклічні посилання, які лічильник сам не подужає.

    import sys, gc

obj = object()
sys.getrefcount(obj)     # напр. 2: саме ім'я obj + тимчасовий аргумент виклику

class Node: ...
n1, n2 = Node(), Node()
n1.peer = n2             # цикл:
n2.peer = n1             # n1 → n2 → n1
del n1, n2               # лічильники не впадуть до 0 через цикл
gc.collect()             # GC знаходить і звільняє цикл  → поверне ≥ 2

    ⚠️ Пастка. sys.getrefcount(x) завжди на 1 більше за очікуване — сам виклик тримає тимчасове посилання на x. Не лякайся «зайвої» одиниці.

    Практичний наслідок для тебе зі Swift: тут немає weak/unowned як частини синтаксису. Цикли розриває GC автоматично, але якщо тримаєш дорогі ресурси (файли, з'єднання) — не покладайся на момент звільнення, закривай явно через with (Модуль 10).

    Інтернінг: чому is іноді бреше на числах¶

    CPython кешує дрібні незмінні об'єкти. Тому деталь реалізації:

    a = 256; b = 256
a is b           # True  — малі int (-5..256) кешовані

c = 257
d = 257
c is d           # True АБО False — залежить від контексту компіляції!

    У межах одного блоку коду (одна функція, один модуль) компілятор може злити однакові константи в один об'єкт — і 257 is 257 дасть True. Між різними блоками (різні рядки в REPL, окремі exec) — False. Рядки-літерали, схожі на ідентифікатори, теж інтернуються.

    ⚠️ Залізне правило. Ніколи не порівнюй значення через is. is — лише для тотожності об'єкта (is None, is some_singleton). Для «чи дорівнює 257» — завжди ==. Інтернінг — це оптимізація CPython, на неї не можна спиратися.

    Mutable vs immutable, hashable¶

    Категорія Приклади Можна як ключ dict / елемент set?
    Immutable int, float, str, bytes, tuple, frozenset, bool так (hashable)
    Mutable list, dict, set, більшість об'єктів ні (за замовчуванням)

    Незмінність → hashability → придатність бути ключем. Це прямий аналог різниці між Hashable value-типами і класами у Swift. Детальніше — у Модулі 03 і 06.

    4. Версії Python та реалізації¶

    • Працюй на 3.13 (стабільна) або 3.14. Не 3.8/3.9 — там немає сучасного синтаксису типів і дженеріків (PEP 695), який зробить перехід зі Swift природним.
    • Системний Python (той, що в macOS «з коробки») не чіпай — він для самої системи. Завжди став окремий (через uv, див. нижче).

    CPython і альтернативи¶

    «Python» — це специфікація мови; реалізацій кілька:

    Реалізація Що це Коли
    CPython Еталонна (на C). 99% випадків. За замовчуванням завжди.
    PyPy JIT-компілятор, у рази швидший на чистому Python Довгі CPU-bound обчислення без C-розширень.
    GraalPy / Jython На JVM/GraalVM Інтеграція з Java-екосистемою.

    Найважливіша деталь CPython — GIL (Global Interpreter Lock): одночасно байткод виконує лише один потік. Це визначає всю модель паралелізму (Модуль 12). У 3.13+ з'явився експериментальний free-threaded білд (без GIL) — теж у Модулі 12.

    5. Сучасний тулінг (2025)¶

    Екосистема Python історично фрагментована (pyenv + virtualenv + pip + poetry + flake8 + black + isort...). Хороша новина: команда Astral консолідувала це у два інструменти, написані на Rust.

    Завдання Старий стек Сучасний вибір Аналог у Swift
    Версії Python pyenv uv (немає — Xcode керує toolchain)
    Віртуальне середовище venv/virtualenv uv —
    Залежності pip + requirements.txt uv SwiftPM
    Лінтер flake8, pylint ruff SwiftLint
    Форматер black, isort ruff format swift-format
    Перевірка типів — pyright або mypy (вбудовано в компілятор)
    Тести unittest pytest swift-testing / XCTest

    uv — головний інструмент¶

    uv замінює pyenv, venv, pip, pip-tools, poetry й pipx водночас. Це найближче до того, як SwiftPM керує всім життєвим циклом проєкту.

    # Встановлення (macOS)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Новий проєкт (створює pyproject.toml — аналог Package.swift)
uv init my-project
cd my-project

# Встановити конкретну версію Python (uv сам її завантажить)
uv python install 3.13

# Додати залежність (аналог .package(...) у SwiftPM)
uv add httpx
uv add --dev ruff pyright pytest   # dev-залежності

# Запустити будь-що в середовищі проєкту
uv run python main.py
uv run pytest

# Синхронізувати середовище з lock-файлом (аналог `swift package resolve`)
uv sync

    uv створює uv.lock — детермінований lock-файл, як Package.resolved. Детальніше про пакети й публікацію — Модуль 11.

    Віртуальні середовища: що це і чому uv run¶

    venv — це ізольована тека (.venv/) з власним інтерпретатором і набором пакетів, щоб залежності проєктів не конфліктували глобально. Класичний робочий процес вимагав «активації»:

    python -m venv .venv
source .venv/bin/activate     # bash/zsh: міняє $PATH, поки сесія відкрита
# .venv\Scripts\activate      # Windows PowerShell
deactivate                     # вийти

    ⚠️ Пастка. «Активація» лише підміняє $PATH у поточній сесії шелу. Якщо забув активувати — pip install поставить пакет не туди, і отримаєш ModuleNotFoundError. Це класичне джерело плутанини.

    uv run робить активацію непотрібною: він сам знаходить .venv проєкту й запускає команду в ньому. Тому в сучасному процесі ти майже ніколи не активуєш середовище руками — просто uv run ....

    ruff — лінтер + форматер¶

    uv run ruff check .          # лінт (знаходить проблеми)
uv run ruff check --fix .     # автовиправлення
uv run ruff format .          # форматування (заміна black)

    Конфіг у pyproject.toml:

    [tool.ruff]
line-length = 88
target-version = "py313"

[tool.ruff.lint]
# E,F — базові; I — сортування імпортів; UP — модернізація синтаксису;
# B — bugbear (типові баги); SIM — спрощення.
select = ["E", "F", "I", "UP", "B", "SIM"]

    pyright — статична перевірка типів¶

    Це те, чого тобі найбільше бракуватиме зі Swift: компілятор, що ловить помилки типів. pyright (від Microsoft, рушій VS Code Pylance) повертає цю безпеку.

    uv run pyright

    [tool.pyright]
typeCheckingMode = "strict"   # для нового коду — одразу strict

    Best practice. Налаштуй pyright у режимі strict із самого початку. Так Python для тебе поводитиметься найближче до Swift: код без анотацій типів підсвічуватиметься як помилка.

    6. Перший проєкт «з нуля»¶

    uv init hello && cd hello
uv add --dev ruff pyright pytest

    pyproject.toml (єдиний файл-маніфест проєкту, аналог Package.swift):

    [project]
name = "hello"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = []

[dependency-groups]
dev = ["ruff", "pyright", "pytest"]

[tool.pyright]
typeCheckingMode = "strict"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM"]

    main.py:

    def main() -> None:
    print("Hello from Python")


if __name__ == "__main__":
    main()

    uv run python main.py
uv run ruff format . && uv run ruff check . && uv run pyright

    Конструкцію if __name__ == "__main__": детально пояснюю в Модулі 11 — поки сприймай як аналог @main у Swift (точка входу, що спрацьовує лише при прямому запуску, а не при імпорті).

    7. Профілювання та вимірювання¶

    Зі Swift у тебе є Instruments. У Python — кілька рівнів, від мікро- до продакшен-профілювання.

    timeit — мікробенчмарк одного виразу¶

    uv run python -c "import timeit; print(timeit.timeit('sum(range(100))', number=100000))"
# напр. 0.0273  — 100k повторів, секунди

    timeit сам прогріває й усереднює — не міряй швидкі операції голим time.perf_counter().

    cProfile — де програма проводить час¶

    uv run python -m cProfile -s cumulative my_script.py

    Дає таблицю викликів із сумарним часом — перше, куди дивитися при «повільно». Для візуалізації — snakeviz (uv run snakeviz profile.out).

    py-spy — профайлер живого процесу¶

    uvx py-spy top --pid 12345        # топ функцій у запущеному процесі
uvx py-spy record -o flame.svg --pid 12345   # flame graph

    py-spy не вимагає правок коду й не зупиняє процес — ідеально для продакшену. (uvx = uv tool run: запуск утиліти без додавання в проєкт.)

    Best practice. Спершу cProfile (де гаряче), і лише тоді оптимізуй. «Чистий Python повільний» — не привід переписувати все; зазвичай 1-2 гарячі функції вирішують або винесенням у NumPy, або кешуванням (functools.cache, Модуль 02).

    8. REPL та інтерактивна розробка¶

    uv run python        # стандартний REPL (у 3.13+ значно покращений: підсвітка,
                     # багаторядкове редагування, кольори)
    • python -i script.py — виконати скрипт і лишитися в REPL з його змінними (швидкий спосіб «помацати» стан).
    • help(obj) і dir(obj) — вбудована інтроспекція: документація і список атрибутів будь-якого об'єкта прямо в REPL.
    • Для серйозної роботи з даними/ML — Jupyter або marimo (сучасніший, reactive-аналог).
    >>> import json
>>> dir(json)          # ['dump', 'dumps', 'load', 'loads', ...]
>>> help(json.dumps)   # повна docstring-довідка

    Підсумок модуля¶

    • Python — динамічна, інтерпретована мова з reference semantics за замовчуванням. Думай «імена-наклейки на об'єктах у купі», не «коробки зі значеннями».
    • Код компілюється в байткод (кеш __pycache__/*.pyc) і виконується у PVM CPython; саме цей шар — причина «повільності» чистого Python.
    • Кожен об'єкт = ідентичність + тип + значення. is — тотожність (як ===), == — рівність. Ніколи не порівнюй значення через is (інтернінг бреше).
    • Пам'ять — reference counting + GC для циклів; дорогі ресурси закривай явно (with).
    • Стек: uv (версії + venv + залежності), ruff (лінт + формат), pyright (strict), pytest. uv run робить активацію venv зайвою.
    • Профілювання: timeit → cProfile → py-spy. Міряй, потім оптимізуй.
    • Працюй на 3.13+, тримай pyright у strict — і Python поводитиметься найближче до знайомої статичної мови.
